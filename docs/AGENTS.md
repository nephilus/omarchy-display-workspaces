# Documentation and screenshot instructions

These rules supplement the repository-root `AGENTS.md`.

## Positioning and disclosure

Keep the problem and differentiators near the top of the README, before installation: simpler display arrangement with confirmation/rollback, workspace visibility across displays, manual named profiles, and a compact no-frills design. Separate **Displays**, **Workspaces**, and **Profiles** when explaining workflows.

Retain a prominent **AI-generated by GPT Astra** caution. Explain unsandboxed execution, configuration risk, review/backups, and the limits of safeguards. Do not replace it with a claim that tests make the plugin safe, audited, official, or compatible with every Omarchy release.

## Contracts to state accurately

- Apply keeps a layout for the current session; names/icons/order persist immediately.
- Profiles save current live state separately, not draft edits or persistent Hyprland rules. Loading is manual and draft-only; matching limits, missing workspaces, private storage, confirmations and backups must be clear. Replace selected recaptures live state even when used to change a name.
- Forget removes supported rules and matching customization, not physical hardware. It requires confirmation, exact backups and guarded recovery; active layout changes are possible.
- Unsupported or ambiguous configurations are refused; do not imply arbitrary Lua can be rewritten.
- The native installer accepts this repository URL because the root manifest is valid. This does not promise a curated catalog listing.
- Use `display.workspaces` in current commands and paths. Keep migration instructions for breaking ID changes without presenting obsolete IDs as supported aliases.

Check commands against the installed native tools or their source. Distinguish tested versions from minimum-version guarantees. Keep examples generic and free of workstation-specific paths, labels and hardware identifiers.

## Screenshots

Use the actual QML components with synthetic display/workspace data. Capture only the component against an opaque, neutral background; never publish an unreviewed full-desktop capture. Do not paint fake controls or show features the plugin does not implement.

Captions must disclose illustrative fixture data and that normal styling/translucency follows the user's Omarchy theme. Wait for loading, animation and glyph rendering to settle. Inspect every image at readable size for clipping, missing text and accidental personal content before committing it.

Store reviewed assets under `docs/images/` and link them from the README with descriptive alt text. Keep only assets actually referenced. Temporary harnesses, command stubs and sample runtime/configuration files stay outside the repository and are removed after capture. Never trigger real monitor mutations to obtain a screenshot.

## Maintenance

Keep README, installation, usage and agent guidance consistent with the implementation. Verify local Markdown links and image paths after moving sections/files. When a screenshot-affecting feature changes, refresh the relevant capture or remove it rather than leaving misleading UI documentation.
